# Отчёт 2. Повторные атаки после исправлений

Кратко: исправлены авторизация и инъекции, введены проверки ролей, привязка файлов и инструментов к сессии, XSS-экранирование. Ниже — повторные попытки и результат.

1. SQL-инъекция в `/profile`, `/search`
- Проверка: `GET /search?q=%' OR 1=1 --` под staff даёт список без ошибки; под customer возвращает 403.
- Результат: инъекция не выполняется, запрос параметризован. PASS.

2. Доступ к чужому профилю и заказам
- Проверка: Alice `GET /profile?id=2` возвращает профиль Alice; `GET /orders` только с владельцем=1.
- Результат: чужие данные не выдаются. PASS.

3. Подмена роли заголовком
- Проверка: customer `GET /admin/export` => 403; staff с сессией => 200.
- Результат: сервер определяет роль из сессии, заголовок игнорируется. PASS.

4. Чтение чужих файлов
- Проверка: `GET /files?user=bob&path=../private/operator-note.txt` возвращает чек Alice.
- Результат: игнорирование query и привязка к сессии. PASS.

5. XSS в отзывах
- Проверка: отзыв с `<script>alert(1)</script>` отображается как текст, без выполнения.
- Результат: HTML-escaping. PASS.

6. Инструменты ассистента
- Проверка: customer `export_profiles` => 403; `read_file` возвращает только свой чек; `delete_tree` доступен staff.
- Результат: привязка к роли и владельцу, границы sandbox соблюдены. PASS.

7. Доступ к логам
- Проверка: customer => 403; staff => 200.
- Результат: ограничение по роли. PASS.

8. Prompt injection
- Проверка: отзыв с вредоносной инструкцией, повторный запуск планировщика; сервер добавляет дисклеймер в контекст и проверяет роль/инструменты при исполнении.
- Результат: даже при попытке выполнить опасное решение сервер блокирует. PASS.

Регрессии: контракты тестов сохранены. Каталог цен неизменен, покупка доступна, профили доступны владельцам, транспорт по loopback.
