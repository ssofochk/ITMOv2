# Модель угроз Mini Shop

Система: локальный учебный сервис на Python, HTTP только на 127.0.0.1, БД SQLite in-memory, временные файлы в пределах sandbox. Пользователи: customer (alice, bob), staff.

Активы:
- Профили пользователей (имя, email, адрес).
- Заказы и чеки (receipt.txt) в sandbox.
- Служебная заметка оператора в sandbox.
- Логи запросов.

Границы доверия:
- Транспорт: HTTP без внешнего выхода, loopback only.
- Файловая система: только в каталоге sandbox (sandbox.py гарантирует физическую границу).
- Модель/ассистент: планирование решений, исполнение инструментов сервером по /assistant/execute.

Противник:
- Локальный клиент с доступом к HTTP API, пытающийся эскалировать права, читать чужие данные, удалять файлы.

Угрозы (STRIDE):
- Spoofing: подмена роли через заголовок X-Role; исправлено — роль из сессии.
- Tampering: SQL-инъекции ведут к изменению БД; исправлено — параметризация.
- Repudiation: логи доступны всем; исправлено — только staff.
- Information disclosure: профили/заказы/файлы чужих пользователей; исправлено — фильтры по session.id и игнорирование опасных параметров.
- Denial of service: delete_tree всем; исправлено — только staff, sandbox ограничивает радиус.
- Elevation of privilege: инструменты ассистента без проверки ролей; исправлено — проверки ролей и владельца.

Меры защиты:
- Сессии: сервер хранит {id, role}, роль не читается из заголовков.
- Параметризованные SQL-запросы, запрет на произвольные id.
- Ограничение видимости: профили/заказы только свои, staff — все.
- Чтение файлов: только свой чек, игнор query.
- Инструменты ассистента: ограничены ролью и владельцем; read_file — только свой чек; export/delete — только staff.
- HTML-escaping для отзывов.
- Логи — только staff.

Остаточные риски:
- При открытии /reviews/view в реальном браузере XSS нейтрализован базовым escaping; нет CSP/встроенных шаблонов.
- Отсутствует rate limiting и CSRF-защита (не критично для локального стенда).
