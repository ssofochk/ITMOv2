# Делим — спецификация бизнес-логики v2 (согласованная)

Версия: v2. Зафиксированы типы, инварианты, алгоритмы и контракты, согласованные с UI.

## 1. Область

- Один счёт, рубли, хранение в `localStorage`.
- Все суммы — целые копейки (`number`). Предел: `0 < amountCents <= 9e15`.

## 2. Типы и модель

- UUID v4 как строки — формат идентификаторов.
- `createdAt` — epoch ms (`number`).
- Участник: уникальное имя (без учёта регистра), `archived?: boolean`.
- Расход: `title` (UI), `amountCents`, `payerId`, `involvedIds[]`, `createdAt`.

## 3. Операции (TS API)

См. единый контракт `docs/contract.md`. Операции атомарны: на ошибке состояние не меняется.

- `addParticipant(state, name)` — проверяет непустоту и уникальность имени; генерирует UUID; устанавливает `createdAt`.
- `removeParticipant(state, id)` — запрещено, если участник фигурирует в истории (`PARTICIPANT_IN_USE`).
- `archiveParticipant(state, id, archived)` — помечает участника; UI может скрывать из выбора новых расходов.
- `addExpense(state, input)` — валидирует поля; допускает плательщика вне `involvedIds`.
- `deleteExpense(state, expenseId)` — удаляет по id; отсутствующий — `EXPENSE_NOT_FOUND`.
- `computeBalances(state)` — возвращает строки баланса.
- `suggestTransfers(balances)` — возвращает детерминированный набор переводов.
- `serialize(state)` / `deserialize(payload)` — JSON, строгая валидация.

## 4. Денежные вычисления

- Деление суммы по участникам: `base = floor(amountCents/N)`, `remainder = amountCents % N`, сортировка `involvedIds` по `UUID`, первыми `remainder` получают `base+1`.
- Инварианты: сумма долей = `amountCents`; доли не отрицательны.
- Плательщик платит свою долю только если входит в `involvedIds`; иначе он кредитор на полную сумму.

## 5. Взаимозачёт (Transfers)

- Формируем `creditors` (`netCents > 0`) и `debtors` (`netCents < 0`).
- Сортируем обе группы лексикографически по `UUID`.
- Жадный алгоритм: идём по должникам; закрываем долг по порядку кредиторов; перевод `min(debt, credit)`; исключаем нули.
- Свойства: детерминизм; сумма по участнику равна `|netCents|`.

## 6. Хранение и ошибки

- Ключ `localStorage`: `delim:v1`.
- `ApplicationState.schemaVersion = 1`.
- Ошибки: коды из контракта (`INVALID_*`, `STATE_*`, `EXPENSE_NOT_FOUND`, и т.п.).
- `deserialize` валидирует: типы, UUID, уникальность id, существование ссылок, суммы > 0, пределы. Нарушение → ошибка, состояние не меняется.
- `serialize` выдаёт компактный JSON.

## 7. Ограничения

- Уникальность имён участников обеспечивается логикой; сравнение без учёта регистра.
- Максимальные размеры списков — не ограничены в модели; производительность — ответственность реализации.

## 8. Приёмочные примеры

- Базовые: совпадают с контрактом (`docs/contract.md`).
- Демонстрация: Аня, Маша, Дима; расходы 4500₽ (Аня, трое) и 1500₽ (Маша, трое) → переводы: Маша → Аня 500₽; Дима → Аня 2000₽.
