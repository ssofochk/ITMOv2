# Открытые вопросы и допущения (UI → Логика)

Требуют согласования перед реализацией логики и интеграции.

Идентификаторы и модели:
- Можно ли зафиксировать формат `id` как UUID (строка)? UI предполагает строки.
- Допустимы ли дубликаты имён участников при различном регистре? UI предполагает уникальность без учёта регистра.

Округления и деление суммы:
- Стратегия округления при делении суммы по участникам (банковское, вверх/вниз, распределение остаточных копеек).
- Точность хранения — два знака после запятой?

Плательщик и множество делящих:
- Разрешён ли кейс, когда плательщик не входит в список делящихся? UI предполагает «да».
- Разрешён ли кейс, когда плательщик входит — UI показывает это явно.

Удаление участника:
- Политика v1: запрещаем удаление, если участник встречается в расходах. Возможен ли «архив»?

Переводы:
- Какой алгоритм минимизации переводов используется? UI ожидает массив пар `fromId → toId` с суммами.
- Нужна ли детерминированность порядка? Если да — по какому ключу сортировать?

Хранение:
- Формат снапшота для localStorage: сериализация `StoreSnapshot` в JSON. Название ключа (например, `delim:v1`).
- Поведение при недоступности localStorage — возвращать ошибку `storage_unavailable`.

Ошибки и коды:
- Базовые коды: `validation`, `conflict`, `storage_unavailable`. Требуются ли дополнительные?

Масштаб:
- Ожидаемые максимальные размеры списков (участников, расходов) для производительности UI.
