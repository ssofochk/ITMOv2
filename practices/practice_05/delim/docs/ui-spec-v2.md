# Делим — UI спецификация v2 (согласованная)

Версия: v2 (согласована с логикой)

1. Цель и сценарии

- Интерфейс для учёта совместных расходов, расчёта балансов и рекомендаций переводов, с локальным сохранением.

2. Основной экран

- Верхняя панель: «Делим», вкладки «Участники», «Расходы», «Балансы», «Переводы»; действие «Очистить данные» (подтверждение).
- Контент активной вкладки; подсказки/дисклеймер.

3. Участники

- Добавление: поле имени + кнопка «Добавить».
- Валидация: имя `trim()` непустое, уникально без учёта регистра. Ошибки — inline.
- Список: карточки с именем; (опционально) метка «архивирован».
- Удаление: недоступно, если участник встречается как плательщик или бенефициар в истории; UI использует `canRemoveParticipant`.
- Архивация: операция может быть доступна позже; если включена — скрывает из выбора, не удаляет историю.

4. Форма расходов

- Поля: название (1–80 симв., `trim()`), сумма (в рублях, шаг 0.01, > 0), плательщик (из участников), участники расхода (мультивыбор, минимум один).
- Распределение: равные доли; неделимые копейки распределяются детерминированно по `UUID`.
- Плательщик может не входить в участники расхода; UI явно показывает это.
- Отправка: «Добавить расход». Ошибки/валидация — inline.

5. История расходов

- Список под формой: карточка с названием, суммой, плательщиком, количеством делящихся (раскрываемый список), временем добавления.
- Сортировка: по времени добавления (убывание `createdAt`).
- Удаление: кнопка «Удалить» → подтверждение → перерасчёт.
- Пустое состояние: текст + «Добавить первый расход».

6. Балансы и переводы

- «Балансы»: таблица/список с «сколько заплатил», «сколько должен был», «нетто», цветовое кодирование (положительный — зелёный, отрицательный — красный).
- «Переводы»: детерминированный список «кто кому сколько должен»; сортировка и состав — согласно бизнес-логике (по UUID, жадный алгоритм). Суммы > 0.

7. Состояния интерфейса

- Пустые данные: информативные.
- Успех: ненавязчивые уведомления.
- Ошибки: inline + тосты. UI мапит `LogicError.code` на русские сообщения.
- Ошибки хранения: при недоступности localStorage — предупреждение, данные не сохранятся.
- Повреждённые данные: предложение сбросить, без потери молча.

8. API ожидания (согласованный контракт)

- Типы и функции — см. `docs/contract.md`.
- Суммы — в копейках; UI отображает рубли с двумя знаками после запятой.
- История — `listExpenses()` по `createdAt` убыванию.

9. Адаптивность и доступность

- Мобильный: нижняя панель; формы — вертикальные; списки — компактные.
- Десктоп: верхняя панель; формы — двухколоночные при ширине; история — карточки.
- Доступность: семантика, aria-метки, управление с клавиатуры, контраст, видимый фокус.

10. Acceptance (ключевые)

- Добавление участника с уникальным именем → успех; дубликат имени (без учёта регистра) → ошибка.
- Добавление валидного расхода → запись в истории сверху.
- Удаление существующего расхода → перерасчёт; удаление несуществующего → ошибка.
- Балансы: сумма всех `netCents` равна нулю.
- Переводы: нет нулевых или отрицательных сумм; детерминизм по UUID.
- Сохранение/восстановление: `localStorage` ключ `delim:v1`; повреждённые данные → ошибка и предложение сброса.
