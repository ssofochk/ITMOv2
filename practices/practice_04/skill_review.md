# Разбор skill `test-driven-development`

Skill задаёт TDD-процесс: сначала формулируется ожидаемое поведение и создаётся тест, который должен упасть, затем пишется минимальная реализация и выполняется повторная проверка. Файл `writing-good-tests.md` дополняет основную инструкцию рекомендациями по качеству тестов и помогает проверять поведение, а не детали реализации. В этой работе skill использовался при разработке `practice-checker`: новые тесты сначала выявили неправильную логику `ok` и определение корня репозитория, после чего реализация была исправлена до GREEN. Сам skill не гарантирует правильность решения, но делает цикл «ожидание → ошибка → исправление → проверка» явным и воспроизводимым.
